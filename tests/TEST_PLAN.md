# План тестирования ADK Constructor v2

Все изменения только в ветке `refactor-v2`. Не объединять с `main`, пока ручные проверки не пройдены.

## Автоматические проверки

В корне клонированного репозитория выполнить:
```powershell
node tests/run-tests.mjs
```
Ожидаемый результат: `12/12 checks passed`. В GitHub Actions также запускается `node tests/browser-e2e.mjs` после установки Playwright. Последний успешный прогон: https://github.com/NATADAU/adk-constructor/actions/runs/44818737361 (12 Node-тестов и 17 Chrome-проверок, включая PDF/PNG/ZIP). Тесты проверяют реальную JavaScript-логику из HTML-файла: синтаксис, раскладку, копии, геометрию кадрирования, расчёт меток и наличие элементов печати. Они не воспроизводят Safari или системный диалог печати.

## Браузерная интеграционная проверка

Открыть `tests/browser-smoke.html` через локальный сервер из корня репозитория, например `python -m http.server 8000`, затем перейти на `http://localhost:8000/tests/browser-smoke.html`. Проверяются DOM карточек, подписи, кадрирование в печатной разметке и метки. **Этот вспомогательный HTML-файл пока не запускался**; отдельный сценарий `tests/browser-e2e.mjs` уже успешно выполнен в Chrome на GitHub Actions.

## Проверка новой логики вкладок

1. Во вкладке «Изображения» убедиться, что под миниатюрой стоят «Изменить кадр» и «Удалить изображение», а количества копий здесь больше нет.
2. Во вкладке «Лист» нажать + и −: количество карточек на самом листе должно измениться сразу.
3. Добавить второе изображение, выбрать его в поле над листом и увеличить количество. У первой картинки количество не должно измениться.
4. Удалить изображение во вкладке «Изображения» и проверить, что список на вкладке «Лист» обновился.

## Ручной чек-лист — iPhone, Safari

1. Открыть тестовую версию локально или в отдельном предпросмотре ветки (НЕ рабочую GitHub Pages).
2. Загрузить портретное и горизонтальное изображение. Проверить, что видна вся ширина интерфейса и нет горизонтального сдвига.
3. Изменить количество копий цифрами и кнопками «+»/«−»; проверить 1, 5, 30.
4. В окне кадрирования проверить масштабы 100, 150, 200 и 300%. При 100% перемещение может быть ограничено, чтобы не возникали пустые поля; после увеличения перемещение должно быть плавным и предсказуемым.
5. Попробовать увести картинку за край — пустые области не должны появляться там, где изображение должно заполнять окно.
6. Добавить подпись в окне кадрирования и применить. Сравнить с листом.
7. Повернуть телефон и проверить поведение окна, ползунка, клавиатуры и вкладок.

## Ручной чек-лист — браузер на компьютере

1. Повторить кадрирование мышкой.
2. Проверить соответствие редактора, предпросмотра и распечатки для квадратной, портретной и широкой картинки.
3. Переключать рамку: обычная, тонкая, без рамки.
4. Проверить общую пунктирную сетку: между карточками нет промежутков и двойных линий; при неполном последнем ряду отсутствуют пустые ячейки. Выключение сетки возвращает выбранный промежуток.
5. Проверить подпись до и после кадрирования, включая длинную подпись.
6. Проверить А4/А3, книжную/альбомную ориентацию, размеры 3, 5, 7 и 10 см и собственный размер.
7. Напечатать тестовый лист с масштабом 100%, линейкой измерить карточку 50×50 мм.
8. «Скачать PDF»: убедиться, что открывается диалог печати, и сохранить PDF через него.

## Проверка экспорта и отправки

1. На iPhone с одной картинкой скачать PDF и убедиться, что файл виден в приложении «Файлы».
2. Открыть PDF в «Файлах»: проверить изображение, подпись и количество копий.
3. Нажать «Поделиться»: должно открыться системное меню с файлом PDF. Проверить отправку в выбранный мессенджер или почту только с тестовым изображением.
4. Скачать PNG: при одном листе должен быть файл .png; при нескольких — архив .zip.
5. На компьютере создать PDF для А4 и А3, сравнить с предпросмотром и распечатать в масштабе 100% без подгонки. Измерить линейкой карточку 50×50 мм.
6. Проверить набор из 30 копий и изображения PNG/JPG/WEBP на реальном телефоне.
7. При значительном объёме (много листов) проверить, не происходит ли нехватки памяти браузера.

## Критерий публикации

Нет критических ошибок. Согласовано поведение кадрирования, подписи не пропадают, на телефоне нет горизонтальной прокрутки, общие линии сетки не дублируются, бумажные размеры соответствуют заданным. Публикация только после разрешения пользователя.
